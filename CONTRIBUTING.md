# Contributing to NT MANAGER

Thank you for your interest in improving NT MANAGER. The project is at an early, documentation-only stage: the repository does not yet include application source code or a build system. Contributions should reflect what is present and must not describe planned behavior as working functionality.

## Ways to contribute

- Improve clarity, grammar, accessibility, or documentation consistency.
- Suggest product workflows with a clear use case and constraints.
- Report inaccurate claims, broken relative links, or documentation issues.
- Propose implementation work once application source code and contribution requirements are established.

## Before opening an issue or pull request

1. Search existing issues and pull requests to avoid duplicates.
2. Describe the user need, expected behavior, and relevant limitations.
3. Label proposals and unverified assumptions clearly; do not claim a feature exists unless it has been implemented and verified.
4. For bug reports, provide reproducible steps and the environment where relevant. There is no executable application to test at present.
5. Keep changes focused and preserve the existing MIT license and project attribution.

## Documentation change checklist

- Use professional, clear English.
- Check relative links against the repository structure.
- Do not invent release versions, dates, downloads, compatibility, or implementation status.
- Protect credentials and private information. Never submit keystore files, passwords, tokens, private APKs, or other secrets.
- Describe APK inspection and decompilation only for applications the user owns or is authorized to analyze.
- Clarify that login UI customization does not implement a secure authentication backend.

## Pull requests

Explain the reason for the change, list the files affected, and note the validation performed. For documentation-only changes, check Markdown formatting and confirm internal relative links resolve. Do not bundle unrelated changes.

Contribution requirements may be expanded when the project adds source code, tests, and an established development toolchain.
